# Spec guidance

Use only the parts that make the outcome clear. The user's format and project conventions take
precedence. A short spec may need only a paragraph of context and a few acceptance bullets.

- **Problem and outcome:** what changes for whom, and why.
- **Scope:** relevant behavior, constraints, and explicit exclusions that prevent likely confusion.
- **Acceptance:** observable results, including material failure cases.
- **Decisions and uncertainty:** settled choices, assumptions, and open questions that affect the
  outcome.
- **Evidence:** links to existing behavior or external sources when a claim depends on them.

Specs have no required heading set, status marker, approval field, commit ID, ledger, or location.
When revising an existing spec, retain useful project-specific structure rather than reformatting
it to match this guide.
