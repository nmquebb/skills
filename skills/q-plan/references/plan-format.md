# Plan guidance

A plan should give an implementer enough direction to act without freezing routine coding choices.
Use the user's preferred form and project conventions. A compact outline is often enough:

1. Outcome and the source specification or request.
2. A small sequence of meaningful changes, with affected owners and important contracts.
3. Dependencies or migration steps that determine order.
4. Focused checks for the behavior that matters.
5. Assumptions or decisions still needed.

Omit inapplicable items. There is no required milestone count, agent assignment, approval field,
ledger, delivery policy, or file path. A plan in conversation is as valid as a plan file.
